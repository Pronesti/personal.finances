# Private extraction helpers

This is part of the backend artifact. It has its own Node lockfile/build and pinned Python environment; it never imports `web/` or frontend source/dependencies. Node extracts receipt structure; PHP independently decides exact-cent admission. Statement extraction is Python. No helper posts money, reads an application environment file, scans a financial installation or calls an OCR provider.

Use Node 24: `npm ci` then `npm run build`. From `backend/`, create `.venv` with a compatible Python 3 and run `.venv/bin/python -m pip install -r processing/requirements.txt`. The recorded machine uses Python 3.14.8 with pdfplumber 0.11.10, PyMuPDF 2.1 and PyObjC 13.0. Apple Vision requires native macOS; a Linux API needs a separately selected private macOS execution boundary. Set `TARJETAS_PYTHON` to the absolute interpreter path. Do not borrow another application's virtual environment.

`statement.py` takes exactly one explicit private PDF path and writes a complete extraction envelope to stdout. It has no batch/default directory behavior. Mercado Pago still needs a year in the temporary PDF filename. Layout and read errors are distinct and occur before accounting admission. `python -m unittest discover -s processing/tests -v` checks the five frozen extraction outcomes using only synthetic files.

`receipt_vision.py` takes an explicit PDF, scale (3/2/1.5), attempt (1/2/3), and canonical private temp root. It renders overlapping slices locally, maps Vision boxes back to whole-page coordinates and deduplicates overlaps. Vision remains Spanish/English regardless of interface locale. It emits private JSON-lines phase events around actual recognition calls. Rendering, process launch, inter-slice work, transit and cleanup remain non-OCR work. A single private lock bounds active Vision work to one job; waiting for it consumes the parent's non-OCR allowance.

Current finite local limits: 20 pages, 16 million rendered pixels/page, 64 million/document and embedded image, 4 million/slice, 160 slices, 20,000 boxes, 512 MiB cumulative PNG output, 64 worker file descriptors, 600 CPU seconds. The launcher supervises aggregate process-family RSS at a 768 MiB ceiling, sampled every 50 ms. This is a sampled cancellation limit, not a hard per-allocation memory guarantee; more adversarial rendering/resource verification is required before readiness. PHP bounds stdout to 4 MiB/stderr to 64 KiB and uses a private process group with kill/reap on cancellation. Temporary directories/files start at 0700/0600. The launcher clears inherited application credentials and preserves only runtime PATH/HOME/locale.

`ProcessingBudget` has monotonic original-request, cumulative non-OCR and cumulative per-attempt OCR timers, with at most three distinct attempts. Slices never restart an attempt. All active checks reject expiry ties. End-event transport delay is charged back to non-OCR work. `fromIngress()` accepts only protected server parameters, never HTTP header versions: request ID, original start, exact start+720000 deadline and measured clock-skew milliseconds. It applies the 1000 ms safety margin. No production guard-disabling or watchdog-fault-injection mode exists. This backend primitive does not implement an ingress start hook, upload timer, proxy queue cancellation, FPM termination or trusted remote-worker transport.

After target approval, installation and helper build, `php vendor/bin/phpunit --testsuite=Processing` exercises transcript extraction and the independent PHP gate, complete issuer output through the bounded PHP process adapter, credential filtering, a real short-budget process-family cancellation, and actual local Vision extraction of the synthetic Coto PDF. It uses only the approved synthetic target/private roots. The recorded Vision smoke reached 13,000 cents/two items at scale 3 in roughly three seconds for the full processing test group. This is not long-request/FPM/ingress or complete receipt workflow acceptance.

Production hosting selection was deferred by the user. Imports are not exposed through HTTP until the composed trusted ingress/admission/cleanup contract and retained receipt workflows are implemented. No external OCR or live-data processing change is authorized or performed by these helpers.
