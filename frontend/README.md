# Tarjetas SPA

Standalone React/TypeScript/Vite application, pinned to Node 24. It builds without PHP, Composer, backend source, private roots or backend secrets.

Run `npm ci`, set `VITE_API_BASE_URL` from `.env.example`, then `npm run dev`. HTTPS `/api/v1` at the real API origin is required. There is no Vite API proxy. `npm run typecheck`, `npm test`, and `npm run build` verify the client artifact. The output is `dist/`; deployment serves it with frontend history fallback to `index.html`, revalidated HTML and immutable hashed assets. Do not use Vite dev/preview as production hosting.

`npm run test:browser` runs Playwright against the separately guarded browser environment and synthetic accounts. Install its Chromium with `npx playwright install chromium`. Trust the local development CA in Node using `NODE_EXTRA_CA_CERTS` when needed; do not disable TLS checks. The committed browser test uses the full Chromium PDF viewer. The backend must be independently guarded, migrated, seeded and running first. Browser tests do not provision/reset databases. Their fixed acceptance commands create synthetic factory users only after the independent disposable-target guard passes. Each journey independently verifies that target before clearing its synthetic rate-limit cache; application throttling remains active. Use `TARJETAS_BROWSER_API_ORIGIN=https://api.tarjetas-browser.test:8445` for the local direct-TLS ingress and the matching ignored Vite browser environment.

Session state exists in memory and Secure cookies. No auth token is written to browser storage. The client requests the CSRF cookie at the API origin and explicitly enables credentialed, cross-origin XSRF transport. 401 clears private state; 419 retains entered values and does not automatically replay mutations. Logout failures remain visible so the user can retry. Original documents are fetched by the authenticated client and opened through a reserved blob viewer, with blocked-popup fallback and cleanup on logout/unmount/viewer closure.

Current screens include authentication, overview and 22 additional analytical destinations, receipt intake/correction/item and funding allocation, statement upload/history, historical receipt/source/refund actions, native accounting and retained source/document viewing. Reports use the exact per-route control matrix and backend-owned projections. `/review`, `/super/review`, `/accounting/settings`, remaining native group/purpose workflows and full recovery/processing/deployment acceptance are still pending; this is not completed 32-destination acceptance.
